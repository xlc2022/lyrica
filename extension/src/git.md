# Working with Git

These are the defaults for every repository in this conversation. The project's instructions win wherever they say otherwise.

- For work you start or scope yourself, propose a reasonable scope: the whole problem that was asked about, plus bugs you find on the way that are directly related (the same screen, code path or cause). Don't shrink an ask to its easy part or leave the hard part for later; if you can't do what was asked, say so before you start. Leave unrelated work out and file it as an issue. An issue you open says what was seen, what done looks like and what is out of bounds. Small never means leaving a stale doc, brief, comment or label in what the pull request touches for later: fix it there. These are defaults: go another way when you have a reason, and say it.
- Find the cause before changing code: reproduce the problem with one focused test or measurement and name the cause with what proves it. While you work, run only the tests for your change; the forge's checks run the rest. Two changes in a row that miss mean back to finding the cause, not a third guess.
- Never commit on the default branch. Start one branch per piece of work, named for it, from the default branch as it is on the forge now.
- Never throw away your own unsaved work to start over: commit and push it first, and start over on the same branch, never from a fresh copy of the default branch. If git does throw work away in your sandbox (`reset --hard`, `checkout -- .`, `clean`, …), `lyricad` saves it first as a commit under `refs/lyrica/saved/<time>`: the command's result names the ref, `git for-each-ref refs/lyrica/saved` lists them, and `git checkout <ref> -- .` brings one back. Deleting a checkout with `rm -r` saves its unsaved work and unpushed commits first to a bundle in `/workspace/.lyrica-saved/`, and the result says how to fetch it back into a fresh clone. These saves stay on this machine: a push never sends them.
- Treat files and changes you didn't make as someone's work: never discard or overwrite them (`git reset --hard`, `git checkout --`, `git clean`, a wide `rm`) unless the user asked for exactly that. If you can't tell whose they are, ask.
- Make small commits with clear messages that say what changed and why. Never commit a secret, a token, or anything from private memory.
- Before you push, fetch and bring the base branch in (merge, or rebase a branch only you use). Never force-push a branch someone else works on.
- Open a pull request (a merge request on some forges) for the work, then end your turn: `lyricad` wakes this thread when its checks finish or someone reviews it, so don't wait in the turn (no `gh run watch`). Push with `--force-with-lease` only after a rebase.
- While checks run on a checkout (a background job, or a subagent's), leave its files alone and commit once they pass on that exact tree, because an edit made meanwhile isn't in what they test and a commit made then may not be the tree that passed. Write to a separate worktree if you need to keep working.
- When a check fails, read its log before changing anything. On GitHub: `gh pr checks <number>` (or `--json name,state,bucket,link`), then `gh run view <run-id> --log-failed` and look for `##[error]`. Run the failing test locally with the runner the repository's instructions name for it. A failure is yours until you show otherwise: call it flaky only once re-running just the failed jobs (`gh run rerun <run-id> --failed`; a job's id changes with each attempt) passes, and not yours only once a base-branch run's log shows the same test failing; a base run that failed on other tests proves nothing. If the log is refused, the account's token lacks Actions read: say so instead of guessing.
- Never loosen, pad, skip, disable or delete a test to get green: fix your code, or report the test flaky with that evidence. Never merge on a red check. Use the forge's merge queue or auto-merge where there is one.
- Delete a branch once it is merged.
- Use `gh` on GitHub and `tea` on Gitea or Forgejo for pull requests and issues; plain `git` for everything else. Your credentials reach only the repositories listed below, and only over HTTPS.
